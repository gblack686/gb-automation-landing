02 Goal 56 words

Make per-tool and per-output-type token attribution the standard level of detail for every GBAutomation agent runtime, and wire the telemetry-report skill to consume it. Today the data exists in Langfuse but is thrown away: reports pull only type=GENERATION and discard the SPAN/TOOL/CHAIN tree that links token spend to the tool that caused it.

03 Why (evidence, 2026-06-02) 202 words

Probing the live ecom traces during the telemetry-report work surfaced four facts:

  1. The tree already exists. Observations come in four types: GENERATION,

    2. SPAN (tool_call:main), TOOL (Tool: read_file, Tool: write_file, Tool: terminal, Tool: skill_view, ...), and CHAIN (Hermes turn end). Every observation carries parentObservationId, so the turn tree is fully reconstructable.

  2. Tools carry no tokens; generations do. Every TOOL observation shows

    3. tok(in=0 out=0). Tokens live only on GENERATION observations (promptTokens / completionTokens + usageDetails). Attribution therefore means joining generations to their tool context via the tree.

  3. Tool args are captured. write_file TOOL input includes the full path

    4. (e.g. /Users/ecom/repos/ecom/docs/PRD-...md), so output by file type is derivable from the extension.

  4. Caching is already excellent but invisible in the report. usageDetails

    5. carries cache_read_input_tokens; the Codex agent runs at a 94.7% cache hit rate (16.6M cached vs 936K full-price input, 12:1 input:output). The report counts only promptTokens/completionTokens, so it under-reports throughput and hides cache efficiency.

The current report also has a standing 54% unknown-model gap: agent-team subagent generations arrive without a resolved model, so they cannot be attributed at all. See plans/2026-05-11-github-canonical-tac-self-improve-team-runner-prd (the telemetry-fix-agent / Skill-Run-Registry line of work).

04 The standard (what "this level of detail" means) 247 words

A. Emission contract (every agent runtime MUST emit)

Field / structureRequirement
Observation treeCHAIN (turn) -> SPAN (tool_call) -> TOOL (named) -> GENERATION, linked by parentObservationId.
TOOL.nameTool: <tool_name> (read_file, write_file, terminal, skill_view, ...).
TOOL.inputFull args, including path for file tools (so output-type + context-bloat attribution works).
GENERATION.modelResolved model id (NOT null/unknown). Closes the 54% gap.
GENERATION.usageDetailsinput, output, cache_read_input_tokens, reasoning_tokens, total.
Structured trace tagsrepo:, branch:, slug:, client:, workflow:, feature: so reports group without keyword guessing.

B. Consumption contract (the telemetry-report skill MUST do)

  1. Pull all observation types for the window (drop the type=GENERATION filter).
  2. Reconstruct each turn tree via parentObservationId.
  3. Attribute generation tokens to tool context:
  • Input-cost of a tool result = tokens the tool's output adds to the next

    • generation's prompt (diff successive generation inputs in the same turn).

  • Output-cost of a tool call = output tokens of the generation that emits

    • the tool_use (e.g. a large write_file body).

  1. Bucket write_file calls by file extension -> tokens by output type.
  2. Surface cache efficiency (hit rate, cached vs full-price input) and

    3. unknown-model % as first-class numbers.

C. Known attribution caveat (canonized, not hidden)

A single generation can fire up to ~10 tool calls in one turn (tool_call_count). Within such a turn, that generation's tokens cannot be split perfectly per tool. Rule: attribute input-cost to the specific tool whose result was ingested; attribute everything else at turn level. Report multi-tool turns as such. This is "directionally correct, not penny-precise" by design.

05 Phases 223 words

Phase 0 — Reuse check (TAC-first, non-negotiable)

  • Extend the existing resources/skills/telemetry-report/ skill; do NOT create a

    • new skill. Reuse score is high (same data source, same renderer). Record as a TAC reuse, not a new-skill build.

Phase 1 — Consumption side (low risk, immediate value)

  • Add a tree-walking extractor (extractors.py: collect_tool_attribution).
  • Extend weekly_telemetry.py to pull all observation types and emit two new

    • sections: Tokens by tool and Output by file type, plus a Cost & Cache Efficiency block (hit rate, cached vs uncached, reasoning tokens).

  • render_html.py: render the new sections as branded cards.
  • Works immediately for runtimes that already emit tool spans (Codex/ecom).

Phase 2 — Emission side (close the gaps)

  • Ensure all three runtimes emit a resolved model + structured tags + tool spans:
  • Codex (ecom) — already emits the full tree; add repo:/slug: tags.
  • Hermes — verify CHAIN/SPAN/TOOL emission across profiles.
  • Claude Code subagents — the 54% unknown-model source; resolve model on

    • subagent spans (the telemetry-fix-agent).

Phase 3 — Enforcement

  • Acceptance criteria below become a gate for any new agent runtime.
  • Add a check to the telemetry skill that flags traces missing model or

    • structured tags (so regressions are visible in the weekly report itself).

Phase 4 — Canonize + backfill

  • This plan + the ADR (2026-06-02-trace-attribution-standard) are the

    • standard of record.

  • Regenerate the ecom + mall report with the new sections as the reference output.
06 Acceptance criteria 49 words
  • Weekly report shows Tokens by tool and Output by file type.
  • Report shows cache hit rate + cached-vs-full-price input.
  • Unknown-model generations < 5% of the window (down from ~54%).
  • Structured repo:/slug: tags present on >= 95% of agent traces.
  • Standard documented in the ADR and linked from the telemetry-report SKILL.md.
07 Reuse / non-goals 46 words
  • Reuse: resources/skills/telemetry-report/ (consumer), the Langfuse REST

    • pattern in llm-observability, and parentObservationId already in the data.

  • Non-goals: penny-precise per-tool token splitting inside multi-tool turns;

    • per-tool latency (a separate, easy add if wanted); changing the deterministic HTML/PDF renderers (they cost zero tokens and stay as-is).

08 Risk notes 43 words
  • Pulling all observation types increases Langfuse API volume ~5-10x per run;

    • keep the page cap and persist raw JSON to /tmp as today.

  • Tree-walk attribution depends on consistent parentObservationId emission; if a

    • runtime flattens its tree, that runtime falls back to turn-level only.
