## Technical Foundation

### Claude Code Architecture Patterns

**Orchestrator-Worker Pattern**:
- Lead agent (Opus 4.5) coordinates strategy and validation
- Specialized subagents (Sonnet 4.5) handle domain-specific tasks
- Cost-optimized workers (Haiku 4.5) for routine operations
- 90.2% performance improvement vs single-agent systems

**Model Selection Strategy**:
- **Opus 4.5**: Orchestration, final validation, reasoning-heavy tasks, extended thinking
- **Sonnet 4.5**: Complex agents, code generation, multi-step tasks
- **Haiku 4.5**: 90% of Sonnet capability, 2x speed, 3x cost savings

**Token Optimization Techniques**:
1. Prompt caching (90% savings on repeated content)
2. Haiku for routine tasks (70-90% cost reduction)
3. Batch API (50% discount on input/output)
4. Extended context pricing (double cost above 200K tokens)
5. Hybrid model approach (Opus uses 76% fewer tokens vs Sonnet)

### MCP (Model Context Protocol) Integration

**Available MCP Servers**:
- AWS: CloudWatch, Pricing API, Systems Manager, Documentation
- Observability: Sentry, Datadog, OpenTelemetry
- Productivity: Figma, Notion, Linear, GitHub
- Communication: Gmail, Slack

**MCP Configuration**:
```bash
# Add HTTP server (remote)
claude mcp add --transport http cloudwatch https://api.aws.com/mcp/

# Add Stdio server (local)
claude mcp add --transport stdio sentry -- npx @sentry/mcp

# Manage servers
claude mcp list
claude mcp get cloudwatch
claude mcp remove cloudwatch
```

### Security & Permissions

**Permission Modes**:
- `default`: Ask for permission per tool
- `plan`: Read-only analysis (safe for exploration)
- `acceptEdits`: Auto-accept code edits with review
- `bypassPermissions`: No requests (use with caution)

**Best Practices**:
- Deny-all baseline with allowlists per subagent
- Short-lived secrets (never in agent context)
- AWS IAM roles (prefer over hardcoded credentials)
- MCP tool output limits (default 25K tokens)
- Sandbox filesystem isolation
