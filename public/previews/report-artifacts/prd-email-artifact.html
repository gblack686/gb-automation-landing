PRD Render & Email Pipeline — branded delivery for every dispatched PRD

The pitch in one line: every PRD dispatched through Hermes lands in greg@gbautomation.xyz as a stylish branded HTML email with colored taxonomy pills, a hero block, and a link to the public render at gbautomation.xyz/prds/<slug>. These double as marketing artifacts — investors, prospects, and partners see the same view.

1. Why this matters

Right now PRDs live in three places:

  • Obsidian inbox form (private, vault-local)
  • Linear ticket (private, login-gated)
  • Markdown file in second-brain/inbox/_archive/

None of these are shareable, stylish, or memorable. We've shipped 4 PRDs in 24 hours (GBA-470, GBA-471 Wave-1/2/3, GBA-472) — each one is a piece of strategy work that should look like GBAutomation made it. Right now they look like commit messages.

Wave-3 just shipped a 15KB PRD with 14 sections. If that lands in Greg's inbox as branded HTML with edge-typed pills and a public URL on gbautomation.xyz, it stops being a build ticket and starts being a marketing surface.

2. Goals (countable)

  1. Every PRD dispatched via the inbox scanner triggers a render pipeline within 30 seconds
  2. Greg receives a branded HTML email at greg@gbautomation.xyz for every dispatch
  3. Every PRD has a public URL at https://gbautomation.xyz/prds/<slug> (Amplify, not Netlify)
  4. Each PRD email shows colored taxonomy pills (build status, wave, client, purpose, priority) pulled from the 5 YAML taxonomies
  5. Email is dark-friendly + mobile-friendly (renders correctly in Gmail web + iOS Mail + Outlook)
  6. Public URL renders the same content as the email, but with more depth (full PRD body, not just summary)

3. Non-goals

  • No CRM / mailing list integration (this is Greg-only for now)
  • No inline HTML rendering inside the email body of the full PRD (we link out — emails over 102KB get clipped by Gmail)
  • No real-time updates after dispatch (snapshot at dispatch time; updates trigger a fresh email if status changes)
  • No replacing the Obsidian form (that stays as the approval gate)

4. Architecture (4 specialist agents)

4.1 prd-html-renderer (Phase A)

  • Owns: ~/.hermes/skills/devops/prd-render-and-email/scripts/render_prd_html.py
  • Reads: any PRD markdown file in second-brain/inbox/_archive/
  • Outputs: 2 HTML files

- prd-<slug>-email.html — inline-styled, Gmail-safe, < 80KB, fits in email body

- prd-<slug>-public.html — full standalone page for the website

  • Components:

- Hero block: logo (terra circle with gb mark), title, one-line description, date

- Pill row: 5-7 colored pills using brand palette (see §6 for color map)

- TOC: auto-generated from ## headings

- Body: markdown rendered with markdown-it, syntax-highlighted code blocks (Prism, atom-dark)

- Footer: "Built by GBAutomation · See more at gbautomation.xyz"

  • Done when: 4 existing PRDs (GBA-470, GBA-471 W1/W2, GBA-472) all render without errors and pass Gmail Litmus preview

4.2 prd-publisher-amplify (Phase B)

  • Owns: ~/.hermes/skills/devops/prd-render-and-email/scripts/publish_prd_public.py
  • Workflow:

1. Copy prd-<slug>-public.html to ~/repos/gb-automation-landing/public/prds/<slug>.html

2. Update a prds-manifest.json index file with all known PRDs (slug, title, date, status, taxonomy)

3. git add + commit with message prd: publish <slug> + git push origin master

4. Amplify auto-deploys on push (no GHA needed per existing convention)

  • Add a new React route /prds/:slug in src/App.jsx that fetches /prds/<slug>.html and renders inside a glass-panel container
  • Add a /prds index route that reads prds-manifest.json and shows a gallery
  • Done when: visiting https://gbautomation.xyz/prds/graphify-sync-wave-3-intelligence-layer shows the full PRD live

4.3 prd-emailer (Phase C)

  • Owns: ~/.hermes/skills/devops/prd-render-and-email/scripts/email_prd.py
  • Uses: gws CLI (Google Workspace) to send via Gmail API as Greg
  • Email shape:

- From: greg@gbautomation.xyz

- To: greg@gbautomation.xyz (self-send for now, list-extensible later)

- Subject: [PRD] <title> — <linear-id>

- Body: the rendered prd-<slug>-email.html

- Plain-text fallback: title + 3-line summary + public URL

  • Headers:

- X-PRD-Slug: <slug>

- X-PRD-Linear-ID: GBA-XXX

- X-PRD-Wave: <wave-number>

  • Idempotency: write ~/.hermes/state/prd-emails-sent.json so we don't re-send the same PRD twice unless the markdown hash changes
  • Done when: dispatching a fresh PRD lands an email in Greg's Gmail inbox within 30 seconds

4.4 prd-dispatch-hook (Phase D)

  • Owns: ~/.hermes/skills/devops/prd-render-and-email/scripts/dispatch_hook.py
  • Wires into the existing inbox scanner: when a form's status flips to submitted AND responses.decision.answer == 'approved', fire this hook
  • Hook calls in sequence: render → publish → email
  • Fallback: if any step fails, write a row to prd_dispatches Supabase table with status='failed' + error message; emit a Telegram alert to Greg
  • Done when: approving any inbox form within 30 seconds results in an email + public URL

7. Email-safe HTML rules (Gmail / iOS Mail / Outlook)

  • Inline ALL styles — no <style> blocks, no external CSS
  • Tables for layout — Gmail strips flexbox in some clients (use <table cellpadding=0 cellspacing=0>)
  • Max width 600px — wider gets cut on mobile
  • No webfonts in email — Newsreader / Inter fall back to Georgia / system-ui
  • Total HTML size < 102KB — Gmail clips at 102KB and shows "[Message clipped]"
  • Use &zwj; for spacing — not <br><br>
  • Public URL prominent — top right of hero block ("View full PRD →")
  • Litmus or Mailtrap preview before going live

9. Pitfalls (learned from jobs-report-render)

  1. Newsreader is NOT in Gmail's allowed font list — always have Georgia fallback inline
  2. Amplify cache invalidation is 5 min — link in email should say "Updated " so Greg knows if he's looking at fresh content
  3. Markdown code blocks with > quotes break Prism — strip leading > before highlighting
  4. gws send hangs without --no-interactive flag; pin that in the email script
  5. iOS Mail dark mode inverts pills — explicitly set both color and background-color (don't rely on currentColor)
  6. Don't use <img> for the logo — base64 inline SVG so it loads instantly + works offline
  7. Don't use Litmus for every test — too expensive; only run Litmus on first PRD of the day, use gws preview for the rest
  8. PRD slug must be filesystem-safe — strip emojis, lowercase, hyphenate (graphify-sync-wave-3-intelligence-layer)
  9. Hash the markdown before re-emailing — only re-send if content actually changed
