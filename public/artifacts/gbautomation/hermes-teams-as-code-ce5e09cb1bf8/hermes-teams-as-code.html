Hermes Teams as Code

The Nous-upstream profile model gives you sealed Hermes runtimes you can clone, distribute, and gateway-isolate. What it doesn't give you is a team contract. This walkthrough separates the two layers, points at the swarms that have actually fired locally, and inventories where their reports land.

01Two layers of teams as code

The Hermes docs cover one layer. The other one is sitting in your .claude/ tree.

A "team" in this stack means two different things, sitting at different runtimes, with different contracts. They compose — but mixing them up is the fastest way to design something that won't run.

Layer 1
Hermes
Per-profile sealed runtimes. Gateway-per-process. Distributable via git.
Layer 2
Claude Code
Declarative teams.yaml + agents + Stop-hook validators.
Glue
MCP
Read-only Hermes bridge surfaces conversations + memory to Claude/Codex.

02Layer 1 — Hermes profiles

Sealed runtimes. upstream Nous

A profile is a complete HERMES_HOME=~/.hermes/profiles/<name> tree containing config.yaml, .env, SOUL.md, sessions, memory, skills, cron, state.db, gateway PID + logs, plus an auto-installed ~/.local/bin/<name> alias. The whole thing is portable (hermes profile export coder → .tar.gz) and distributable as a git repo.

→The swarm-enabling primitives

PrimitiveWhat it actually does
Per-profile gateway One OS process per profile. coder gateway start, assistant gateway start. Concurrent only because they're separate processes. No documented swarm/scheduler primitive.
Token lock Refuses to start a second gateway with a duplicate Telegram/Discord/Slack/WhatsApp/Signal token. Prevents silent-double-poller bugs.
gateway install Generates a hermes-gateway-<profile> systemd unit / launchd plist. The team persists as N OS services, not a parent supervisor.
--clone / --clone-all / --clone-from The only "team templating" story upstream. Config-only or full state, from any base.
Profile distributions Closest thing to a teams manifest. hermes profile install github.com/you/research-bot. Ships SOUL + config + skills + cron + MCP. Excludes credentials, memory, sessions.

→The cheat-sheet

# clone-create the canonical Kanban workers
hermes profile create researcher --clone --no-alias
hermes profile create coder      --clone --no-alias
hermes profile create reviewer   --clone --no-alias
hermes profile create ops        --clone --no-alias

# run, switch, install as a service
coder chat
hermes -p coder doctor
hermes profile use coder
coder gateway install           # → hermes-gateway-coder launchd plist

# export / share as a distribution
hermes profile export coder     → coder.tar.gz
hermes profile install github.com/you/research-bot --alias
What's missing upstream — and you've had to invent locally:
  • No team-wide orchestrator. Profiles don't talk to each other except through Kanban (Level 5) or external surfaces.
  • No declarative teams.yaml. The closest is your specs/2026-05-04-hermes-operations-subsystem.md § 14.1.
  • No swarm-level observability. Langfuse is bolted on via resources/lib/tracing.py, not Hermes-native.

03Layer 2 — Claude-Code agent teams

The build-time contract. agent expert workflow

specs/2026-05-04-hermes-operations-subsystem.md is your fully-worked example of teams-as-code at the Claude Code layer. It doesn't run a single Hermes process — it builds the subsystem that operates on Hermes.

ComponentWhereCount

Stop-hook validators.claude/hooks/validators/8 — one per deliverable, all blocking on failure

Hermes profiles are the runtime. The Claude-Code .claude/agents/ + teams.yaml is the build-time team contract. The validators turn "teams as code" into "teams that pass CI."

07Bottom-line mental model

Hermes profiles = isolated runtimes, gateway-per-process, token-locked across 5 chat surfaces, distributable via hermes profile install github.com/.... No native orchestrator. Kanban (Level 5) is the upstream's only multi-agent coordination primitive.

Your TAC team contracts in .claude/agents/ + teams.yaml + Stop-validator hooks = the actual "teams as code" artifact. Declarative, validated, reusable. The PRD at specs/2026-05-04-hermes-operations-subsystem.md is the reference shape.

Observability is bolt-on via Langfuse tags. The local swarm is well-instrumented. The GHA swarm is dark — fix the three repo secrets first.
