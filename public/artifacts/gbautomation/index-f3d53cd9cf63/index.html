02 § 1 Product Thesis 139 words

The Mall App is a personal-mall consumer app -- users curate their own feed of indie brands they love. To make that feed alive (not stale), the app needs a backend that continuously knows what those brands are doing: new drops, price changes, sales, sellouts. Sprint 1 ships the first half of that backend: an agent that crawls and maps brand surfaces (Instagram + Shopify storefronts to start), lands canonical data in Supabase, runs on a schedule, and alerts when something interesting changes.

By Day 14 (Monday 2026-06-01, 5pm ET review), we expect to demo a live Supabase view showing 3-5 of Sreya's tracked brands with full catalogs + a real price-change alert firing through the chosen channel. Day 14 also locks the data schema and alert taxonomy with Sreya's input -- the proposed v0 in §§ 5-6 is for her remarks, not sign-off.

03 § 2 Sprint Goal 60 words

Stand up the "agent + watch loop" half of The Mall App backend in 14 days.

Acceptance:

  1. Agent runs unattended for 48 hours on Mac Mini without crashes or manual reset
  2. ≥3 brands tracked end-to-end (catalog ingested, history retained, current-state queryable in Supabase Studio)
  3. ≥1 real price-change or sale event fires an alert through the channel Sreya picks

06 § 5 Proposed Data Schema (v0 -- for Sreya to refine) 354 words

Four tables. DDL below is the starting point; Sreya's answer to § 7 Q1 will refine mall_items columns. raw_json columns kept everywhere so we can replay/migrate when the schema changes.

-- 001_mall_brands.sql
create table if not exists mall_brands (
  brand_id        uuid primary key default gen_random_uuid(),
  handle          text not null,                   -- 'vaincourt_paris', 'themall.app'
  platform        text not null,                   -- 'instagram' | 'shopify' | 'woocommerce' | ...
  source_url      text not null,                   -- canonical scrape URL
  display_name    text,
  status          text not null default 'active',  -- 'active' | 'paused' | 'errored'
  scrape_cadence  text not null default 'daily',   -- 'hourly' | '6h' | 'daily' (Sreya picks)
  last_scraped_at timestamptz,
  created_at      timestamptz not null default now(),
  unique (handle, platform)
);

-- 002_mall_items.sql -- v0 schema, expect to evolve after Sreya's input
create table if not exists mall_items (
  item_id            uuid primary key default gen_random_uuid(),
  brand_id           uuid not null references mall_brands(brand_id),
  source_item_id     text not null,                -- platform-stable id (Shopify product id, IG post id)
  item_type          text not null,                -- 'product' | 'variant' | 'post' | 'reel'
  title              text,
  description        text,
  url                text,
  image_urls         jsonb,                        -- array of URLs (or local paths once we download)
  price              numeric(10,2),
  currency           text default 'USD',
  sale_price         numeric(10,2),
  compare_at_price   numeric(10,2),
  available          boolean,
  raw_json           jsonb,                        -- full source-platform record (so we can re-derive)
  first_seen_at      timestamptz not null default now(),
  last_seen_at       timestamptz not null default now(),
  removed_at         timestamptz,                  -- set when an item disappears from a brand's catalog
  unique (brand_id, source_item_id)
);

create index idx_mall_items_brand on mall_items (brand_id, last_seen_at desc);
create index idx_mall_items_on_sale on mall_items (sale_price) where sale_price is not null;

-- 003_mall_price_history.sql -- append-only, drives sale + price-drop detection
create table if not exists mall_price_history (
  history_id   uuid primary key default gen_random_uuid(),
  item_id      uuid not null references mall_items(item_id),
  price        numeric(10,2),
  sale_price   numeric(10,2),
  available    boolean,
  scraped_at   timestamptz not null default now()
);

create index idx_price_history_item on mall_price_history (item_id, scraped_at desc);

-- 004_scrape_runs.sql -- mirrors the outbound_runs telemetry pattern
create table if not exists scrape_runs (
  run_id          uuid primary key default gen_random_uuid(),
  brand_id        uuid references mall_brands(brand_id),
  source_handle   text not null,
  source_platform text not null,
  status          text not null,                   -- 'ok' | 'partial' | 'failed'
  item_count      integer,
  duration_ms     integer,
  output_dir      text,                            -- ~/.openclaw/workspace/mall-scraper/<handle>/<YYYY-MM-DD>/
  error_tail      text,                            -- truncated stderr if failed
  payload         jsonb,                           -- extensible per-run metadata
  scraped_at      timestamptz not null default now()
);
07 § 6 Proposed Alert Taxonomy (v0 -- for Sreya to refine) 94 words

Five event types. v0 candidate -- Sreya picks which matter and where they land.

EventTriggerDefault Channel
item.newmall_items insert for an existing brandDaily digest
item.removedremoved_at set (item disappeared from brand's catalog)Daily digest
item.on_salesale_price first appears for an itemTelegram (instant)
item.price_dropprice dropped > X% vs. baseline (X = 10% default)Telegram (instant)
item.restockedavailable goes false → trueDaily digest

Per the existing @gbauto_hermes_bot Telegram bot pattern, alerts fire to the chat Sreya designates. Email digest is the alternative if she prefers (less noisy, daily roll-up).

08 § 7 Open Questions for Sreya 194 words

The five we need answered before Friday (2026-05-29) to land everything by Monday's review:

  1. Data fields -- Beyond what's in v0 (title, description, price, image, available, sale_price), which fields matter? Candidates: sizes[], colors[], materials, vendor_url, in_stock_count, shipping_notes, tags[], product_type. Tell us which to add and which to skip.
  2. Photos -- How many per item (1 hero / 3-5 / all variants / all)? Max resolution? Where do they live: Supabase Storage (we host), link-only (we just store the brand's CDN URL), or both (link-only at first, download on-demand)?
  3. Alert types -- Which of the five events in § 6 matter? Where do they land -- Telegram (@gbauto_hermes_bot in a chat you join), email digest to you + Ellie, in-app push later, or somewhere else? What's the price-drop threshold % that's worth a notification?
  4. Brand list (v1) -- What's the starting set of brands the agent should track? The five from your 2026-05-16 reel (@vaincourt_paris, @amanustudio, @dehanche__, @blowthebelt, @streetsaheadusa) or a different shortlist? Have direct storefront URLs (Shopify is cheaper to scrape than IG)?
  5. Cadence -- How fresh do prices need to be: daily, every 6 hours, or hourly? (Hourly is fine technically; the only constraint is being respectful to brand sites.)
