Plan — vault-audit skill (graph hygiene + orphan curation)

Why this exists

[[2026-04-28-graph-hygiene-tactics]] adopted six tactics for keeping the graph readable and explicitly listed /vault-audit as a planned-but-not-built sixth. A first-pass classifier produced outputs/orphan-audit.md with 201 candidates, but the rules were too lenient — the report wasn't actionable. We also now have two new pieces of intelligence the v1 classifier didn't have:

  1. QMD is indexed ([[2026-04-28-obsidian-mind-vendor]]) — we can ask "what are the top-3 semantic neighbors of this orphan?" and emit them as [[suggested-link]] candidates in the report.
  2. MOC convention is locked ([[2026-04-28-no-index-md-convention]]) — every topical folder either has _<folder>.md or shouldn't have a folder at all. The audit can detect both regressions.

validate-write.ts (PostToolUse) covers per-file hygiene at write time. vault-audit is the periodic vault-wide sweep — different scope, different cadence. The two are complements, not duplicates.

Scope

A skill (invokable as /vault-audit) that runs four sub-audits and emits a single remediation report. Read-only by default — never mutates the vault. Mutations happen via separate, explicit follow-up scripts (already proven pattern: outputs/index_cleanup.py).

Sub-audit Question it answers Output
orphans Which notes have zero inbound + zero outbound [[…]]? Why? Classified table — stub / archive / missing-link / artifact / unclassified
mocs Which non-trivial folders lack _<folder>.md? Which have _index.md regressions? Folder list with recommendation (create MOC / promote to flat / delete)
conventions Which notes violate frontmatter / tag / wikilink rules vault-wide? Per-rule violation count + sample paths
excludes Which paths are in the graph but should be excluded? Which are excluded but shouldn't be? Diff against [[2026-04-28-graph-hygiene-tactics]] exclude list

Sub-audits run independently; full runs all four.

Architecture

Skill lives at the gbautomation root — we work from gbautomation/, not from inside second-brain/, so the skill belongs alongside other root-level tooling. Vault path is configured, not implicit.

gbautomation/.claude/skills/vault-audit/
├── SKILL.md                    # Skill manifest (frontmatter + invocation guide)
├── audit.ts                    # Main entry; subcommand dispatcher
├── classifiers/
│   ├── orphan.ts               # Orphan taxonomy + per-note classification
│   ├── moc.ts                  # _<folder>.md presence + _index.md regression check
│   ├── convention.ts           # Reuses validate-write.ts rules vault-wide
│   └── excludes.ts             # Diffs .obsidian/app.json against ADR exclude list
├── lib/
│   ├── qmd-suggest.ts          # Top-N semantic neighbors via qmd CLI
│   ├── vault-root.ts           # Resolve VAULT_ROOT (env override → default `second-brain/`)
│   └── report.ts               # Markdown report writer
└── tests/
    └── classifier.test.ts      # Locks classifier rules — re-runnable on every PR
  • Vault root resolution. lib/vault-root.ts returns process.env.VAULT_ROOT if set, else <gbautomation-root>/second-brain. Required because the skill is one level above the vault and can't use import.meta.url-relative paths the way second-brain/.claude/scripts/ does.
  • Reusing obsidian-mind validators. classifiers/convention.ts imports from second-brain/.claude/scripts/lib/ via relative path (../../../second-brain/.claude/scripts/lib/...). When a second client vault adopts this skill, the import path becomes the configurable bit — but for now, gbautomation's vault is the only consumer.
  • Report output. outputs/vault-audit/<YYYY-MM-DD>-report.md at the gbautomation root (matches how outputs/orphan-audit.md already lives).
  • Runtime. bun (matches second-brain/.claude/scripts/, sidesteps the OneDrive + Node 23 libuv issue).

Orphan taxonomy (the v1 was "too lenient")

A note is an orphan if it has zero inbound wikilinks AND zero outbound wikilinks. The classifier then assigns one of these labels:

Label Detection rule Recommended action
auto-gen-stub Body contains _TBD_ / Auto-generated / ## Files Referencing markers AND no human edit since last update-wiki run Delete on next update-wiki regen; ignore in report unless count balloons
archive Path matches one of the exclude folders from [[2026-04-28-graph-hygiene-tactics]] (_archive/, drafts/sent/, intelligence/correspondence/…) Already excluded from graph; ignore
missing-link Has frontmatter, has body, was edited by a human (commit author ≠ generator), but lacks any [[…]] Actionable. Emit with top-3 QMD neighbors as suggested links
dead-end-leaf Has body content, but is the deepest leaf in a chain that nothing links to Suggest backlinking from _<folder>.md MOC
artifact Filename matches *-backup-*, *.brain-backup-*, **/2026-*-lint-report.md Recommend File Ignore plugin pattern; not a real orphan
unclassified None of the above Surface for human review — these are the ambiguous ones

The lenience bug in v1 was treating auto-gen-stub and missing-link the same. The new rules separate them so the report only highlights what a human can act on.

Phased plan

Phase 0 — TAC-first intake + spec lock

  1. Re-read [[2026-04-28-graph-hygiene-tactics]], [[2026-04-28-no-index-md-convention]], validate-write.ts, classify-message.ts, qmd-mcp.mjs. Confirm the reuse audit table above survives contact with the actual code.
  2. Run a single QMD query end-to-end (npx qmd query "fish-group billing") to confirm latency budget — if P95 > 500ms per query, qmd-suggest.ts becomes batched (one query per 10 orphans, not one per orphan).
  3. Lock the orphan taxonomy. Anything ambiguous after the spec lock either gets a unclassified bucket or a TAC-no-match note before code ships.

Phase 1 — Classifier core (read-only, no QMD yet)

  1. audit.ts skeleton with subcommand dispatcher (orphans, mocs, conventions, excludes, full).
  2. classifiers/orphan.ts — implements the six-label taxonomy above. Walks the vault, parses frontmatter (reuses validate-write.ts parser), counts inbound/outbound [[…]].
  3. classifiers/moc.ts — for every directory under second-brain/, checks for _<dirname>.md; flags any _index.md (defensive — they're all gone, but generator regressions are real).
  4. lib/report.ts — emits outputs/vault-audit/<YYYY-MM-DD>-report.md with one section per sub-audit. Frontmatter includes audit hash so two consecutive runs over the same vault produce identical reports (testable).
  5. Verification: report on current vault matches the manually-curated subset of outputs/orphan-audit.md for the obvious cases (every auto-gen-stub and archive is correctly labeled).

Phase 2 — QMD link suggestions

  1. lib/qmd-suggest.ts — invokes qmd query "<note basename + first-paragraph keywords>" per missing-link orphan. Returns top-3 neighbors above a similarity threshold (start at 0.55, tune).
  2. Threshold below 0.55 → emit suggestion as "weak — review before linking" (we want false positives over false negatives in suggestions; the human curates).
  3. Cache results keyed by file path + mtime so re-running the audit doesn't re-query QMD for unchanged files.
  4. Verification: for 10 known-good orphans (notes a human can identify the correct link for), QMD top-3 must contain the correct link in ≥ 7 cases. If miss rate > 30%, threshold or query construction needs adjustment before shipping.

Phase 3 — Convention + excludes audits

  1. classifiers/convention.ts — runs validate-write.ts's rule set across every .md in the vault (not just one file). Aggregates counts per rule, lists top-N offenders.
  2. classifiers/excludes.ts — reads .obsidian/app.json userIgnoreFilters, diffs against the ADR's exclude list. Reports adds + drops.
  3. Verification: running on a vault with a known convention violation injected (e.g., a frontmatter-less note in os/) produces a report that surfaces it.

Phase 4 — /vault-audit slash command + skill manifest

  1. SKILL.md written following the existing skills' frontmatter pattern. name: vault-audit, description: Vault-wide audit — classify orphans, detect missing MOCs, flag convention violations, suggest QMD-backed links. Read-only, emits report to outputs/.
  2. Wire as /vault-audit [orphans|mocs|conventions|excludes|full]. Default: full.
  3. Add to capabilities/skills-index.md (auto-populated, but a manual entry survives the next regen).

Phase 5 — First-run curation + ADR closeout

  1. Run /vault-audit full against the live vault.
  2. Triage the missing-link and unclassified buckets manually — fix in batches of 20.
  3. Update [[2026-04-28-graph-hygiene-tactics]] application checklist: mark "Re-run orphan audit with stricter rules" as complete; link to first-run report.
  4. Decide: do we want a weekly cron to re-run? Probably yes once the report is actionable. Defer to /schedule after first-run curation proves the rules hold.

Verification (end-to-end)

  • Skill invocation: /vault-audit full exits 0, writes outputs/vault-audit/<date>-report.md, no vault mutations.
  • Determinism: two consecutive runs against the same vault produce identical report bodies (hash check).
  • Reuse: every classifier component imports from existing .claude/scripts/lib/ — no new frontmatter parser, no new wikilink detector, no new matcher.
  • Test coverage: tests/classifier.test.ts locks the six-label taxonomy with known fixtures.

Risks + mitigations

  • QMD latency on full-vault sweep. 1,594 notes × N queries could be slow. Mitigation: only the missing-link bucket gets QMD (typically << 200 notes), and qmd-suggest.ts caches by path+mtime.
  • Classifier still too lenient. The fix for v1 lenience is the explicit six-label taxonomy + Phase 1 verification against manual curation. If the report after Phase 1 still has > 10% noise, taxonomy gets another rule before Phase 2 ships.
  • Skill scope creep into mutation territory. Hard line: this skill never writes to vault notes. Fixes ride on separate scripts (mirroring outputs/index_cleanup.py's pattern). If the temptation to add --auto-fix arises, that's a different skill.
  • Generator regression. update-wiki could re-emit _index.md files. Mitigation: classifiers/moc.ts flags any new _index.md as a hard violation; running /vault-audit weekly catches regressions within 7 days.
  • Convention drift across client vaults. Other client repos (fisch-group, jid5274, greg-trading) have their own vaults. This skill is gbautomation-vault-shaped today; client vaults adopt by copying SKILL.md + classifier files into their own .claude/skills/vault-audit/. Cross-vault sharing is a Phase-N concern, not Phase 0.
