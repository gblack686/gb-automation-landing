02 1. The three-layer model (don't build three competing systems) 139 words

The recent work produced three overlapping "stop hand-editing configs" mechanisms. The ecom Client-Contained Hermes Runtime Boundary ADR (ecom@879831c) defines how they layer:

2. Prompt (runtime)Canopy adapter (hermes prompts)SOUL.md + system_prompt_addendum via base + mixins + paramsengine Step-1 only (gelby-default); multi-profile/cross-tenant deferred upstream

Rule (from the boundary ADR): shared Hermes owns framework + profile registry + lease/CDP primitives + Kanban resolution + TAC gates. Clients own workflow controllers, prompts, validators, tests. The template (hermes-gbauto) renders the client-local layer; the shared core is referenced/pinned, never copied per-client.

03 2. Canopy — what it is and the Step-1 constraint 177 words
  • Canopy = jayminwest/canopy, CLI binary cn (pinned 0.2.6). Prompt composition:

    • base prompt + mixins (inherits:) + variables ({{var}}) + section overrides.

  • Hermes adapter: hermes_agent/prompt_library/ (engine commit 96d222e52), CLI

    • hermes prompts {render,apply,list,receipts,doctor}. Manifests at ~/.hermes/prompt-library/profiles/<profile>.yaml, schema hermes.prompt_profile.v1. Manifest keys: profile, tenant, owner, render.prompt, targets (soul / config_addendum), section_routes, params (scalars only), cross_tenant_inherit_allow. Validation V1–V15 (V14 = cross-tenant guard; V15 = gelby-default has no config_addendum). Apply emits a fossilization warning + auto-backup.

  • CONSTRAINT (load-bearing): the adapter is Step-1 only — only gelby-default is live.

    • Steps 2–5 (Ecom, Carlos, TAC Director, team handoffs, cross-tenant inheritance) are deferred upstream in hermes-agent. Also requires the external cn binary on PATH.

Decision (operator, 2026-06-17): scaffold now, activate at Step 2. Add the Canopy structure to the template now (base persona + the shared TAC-contract mixin + per-client params, all parameterized via copier), but keep the flat config.yaml system_prompt_addendum as the active path. Switch the runtime hermes prompts apply path on when engine Step 2 ships. Zero engine dependency to land the scaffold; kills prompt duplication immediately.
