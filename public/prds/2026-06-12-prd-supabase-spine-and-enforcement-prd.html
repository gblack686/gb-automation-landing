02 Purpose 117 words

PRDs are the practice's unit of intent, but they live only as markdown. There is no PRD object in Supabase — prd_artifacts and sprint_rock_prd_links both return UndefinedTable (the 2026-06-11 migration was written but never applied), the index_prds.py --sync-supabase path has never run, and conformance to gbauto-prd.v1 is enforced by nothing (advisory skill text only, versus enforce-linear-frontmatter.py which actually blocks task writes).

The consequence shows up directly in this sprint's report: every shipped plan is graded "partial" because there is no closed loop from PRD → rock → card → commit → PR → validation. This PRD builds that spine: a live, populated PRD table; a blocking conformance gate; and a join that lets reports prove what a plan actually shipped.

03 Goals 108 words
  • Apply the prd_artifacts + sprint_rock_prd_links migration to Supabase

    • gbauto and populate it by running index_prds.py --sync-supabase.

  • Add a blocking PostToolUse write-hook that rejects PRD writes which violate

    • gbauto-prd.v1 (required frontmatter title/client/status/priority + the seven required sections), mirroring enforce-linear-frontmatter.py.

  • Phase enforcement so legacy PRDs are warn-only and only PRDs declaring

    • schema_version: gbauto-prd.v1 (or newly created PRDs) are hard-blocked — honoring the standing "do not churn all 150 historical PRDs" decision.

  • Join each PRD to its commits and PRs (via branch / source_refs + the

    • gh CLI) and surface that join in the sprint report and plans index.

  • Backfill gbauto-prd.v1 frontmatter for the active sprint PRDs only.

06 Acceptance Criteria 98 words

  • Writing a PRD with schema_version: gbauto-prd.v1 but a missing

  • The hook adds < 200ms and has a passing unit test (good + bad fixtures).
  • The sprint report's "Plans Executed" rows show merged PRs per plan

    • (e.g. PR #174 → crawl-resilience plan).

  • A host-job-run.v1 receipt for the build exists in host_job_runs.
07 Risks 116 words
  • 150-file breakage: a naive blocking hook would reject every legacy PRD on

    • next edit. Mitigation: phased enforcement keyed on the schema_version declaration (warn legacy, block declared/new).

  • Supabase connectivity: prior sync attempts were blocked on DB connectivity;

    • the sprint plan logged this. Mitigation: use gbauto-supabase pooler-session mode (the documented PC path); confirm whoami before migrate.

  • PR-join accuracy: branch→PRD mapping is heuristic. Mitigation: prefer

    • explicit source_refs.branch / source_refs.pr in frontmatter; fall back to slug match and mark low-confidence joins.

  • Hook false-positives on non-PRD plans in the same dirs. Mitigation:

    • require a PRD marker (prd_type/markers) before enforcing.

  • Secret exposure: none introduced; all DB access via gbauto-supabase CLI

    • (AWS-SM credentials), no keys in argv or git.
