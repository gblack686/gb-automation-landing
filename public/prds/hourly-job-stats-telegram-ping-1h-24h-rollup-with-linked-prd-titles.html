Hourly Job-Stats Telegram Ping — 1h + 24h rollup with linked PRD titles

One short Telegram message every hour. Shows what shipped, what's building, what failed — last hour and last 24h. Every PRD/build title is a hyperlink to its rendered HTML on gbautomation.xyz/prds/<slug> (from GBA-473).

1. Why

You already get jobs-pulse-15min and the auto-commit pings. Those are operational noise. This ping is a signal-only digest — once an hour, what's actually moving. Anything with a title links out to the branded HTML page so you can tap and read on the phone.

If the hour was silent (zero events), the ping is suppressed entirely — no "nothing happened" pings.

2. Goals (countable)

  1. Telegram message fires at :00 every hour from 7am to midnight PT
  2. Message contains two rolling windows: last 1h + last 24h
  3. Every PRD/build title is a tappable hyperlink to gbautomation.xyz/prds/<slug> (or the markdown if not yet rendered)
  4. Message is silent when zero events in last hour
  5. Total message length under 4096 chars (Telegram cap)

3. Message shape

📊 GBAuto pulse — 11:00 PM PT


⏱ Last 1h


• 1 PRD dispatched: graphify-sync wave-3


• 2 commits to main


• 0 builds finished


• 0 failures



📅 Last 24h


• 5 PRDs dispatched · 3 shipped · 0 failed


• 12 commits to main · 4 Linear issues closed


• Top: PRD render &amp; email pipeline


• Top: graphify-sync wave-3



🔧 Health: 16 crons OK · 1 erroring (mirror-hermes)

4. Data sources

StatSource
PRDs dispatched (1h/24h)`skill_outputs` where `output_type='prd_dispatch'`
Builds finished`cron_runs` + `skill_runs` joined, GBA-454 schema
Failures`skill_runs.status='failed'` or GHA conclusion=failure
Commits`git log --since=1.hour main` in `~/repos/gbautomation`
Linear closedLinear GraphQL: issues with `state.type='completed'` updated in window
Cron health`hermes cronjob list --json`, count last_status==error
PRD slugs`skill_outputs.output_data->>'slug'` joined to `public_url`

All queries run via urllib (no Supabase SDK), 5-second timeout, JSONL fallback if Supabase unreachable.

5. Script (~/.hermes/scripts/hourly-job-pulse.sh)

  • no_agent: true cron (no LLM cost)
  • Reads SUPABASE_URL + SUPABASE_SERVICE_KEY from AWS Secrets Manager (existing pattern)
  • Builds the message using Python (hourly_pulse.py)
  • Exits silent (empty stdout) when hour was zero-event → cron framework suppresses delivery automatically
  • Otherwise emits Markdown to stdout, cron framework delivers to Telegram home channel

6. Cron registration

schedule: 0 7-23 * * *      # top of every hour, 7am-11pm PT

deliver: origin              # Greg's Telegram home


script: hourly-job-pulse.sh


no_agent: true


name: hourly-job-pulse

Quiet hours: midnight to 6am skipped.

7. Hyperlinks

Markdown links work natively in Telegram (title). Two cases:

  1. PRD has been rendered+published (GBA-473 pipeline ran): link to https://gbautomation.xyz/prds/<slug>
  2. PRD not yet rendered (rendering pending or failed): link to the GitHub raw markdown at https://github.com/gbauto/gbautomation/blob/main/second-brain/inbox/_archive/<date>/<slug>.md

The script checks skill_outputs for a prd_dispatch row matching the slug to decide which URL to use.

8. Pitfalls

  1. Telegram strips Markdown if any character in the message confuses its parser — wrap titles in []() only, no nested formatting
  2. Long PRD titles get truncated visually but the link still works
  3. cron_runs queries that span timezones — always use UTC in SQL, convert for display only
  4. Skip the ping during builds-in-progress windows that span the hour boundary (don't double-count)
  5. Silent hours mean truly silent — empty stdout, not "no events"; the cron framework treats empty as "skip delivery" when no_agent=true

9. Tests

  • tests/test_message_shape.py — golden file for 4 scenarios (busy/quiet/all-failing/mixed)
  • tests/test_link_resolution.py — slug → URL resolves correctly in both rendered + raw cases
  • tests/test_silent_hour.py — zero-event hour returns empty string
  • tests/test_under_4096.py — even worst-case (50 events) fits in Telegram limit

10. Build sequence (1-day vibe-build)

  • Morning: hourly_pulse.py lands with stub data
  • Afternoon: wire real Supabase queries + Linear + git
  • Evening: register cron, run for 3 cycles, verify

11. Acceptance

  • Pings arrive at :00 every hour 7am-11pm PT
  • Zero-event hours produce zero pings
  • 100% of PRD/build titles render as tappable links
  • Tests pass: pytest ~/.hermes/scripts/tests/test_hourly_pulse*.py
  • 1 week of pings reviewed by Greg, signal-to-noise judged acceptable

12. Out of scope

  • Inline charts (text only for now)
  • Per-client breakdowns (will add when we ship per-client dashboards)
  • Reply-to-ping interactions (no commands yet, read-only)
