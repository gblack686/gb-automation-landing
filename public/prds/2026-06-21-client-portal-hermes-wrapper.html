01 Overview 47 words

Turn apps/client-portal/ into a Hermes-dashboard "wrapper": every page inherits a left sidebar; the landing page looks like the Hermes dashboard (GB logo right of the Hermes agent logo); sign in as the ecom client and land on the dashboard; the Chat tab actually communicates with Hermes.

02 Locked decisions (2026-06-21, Greg) 98 words
  • Theme = Variant 1 "Report Paper" from artifacts/hermes-theme-options.html — frosted

    • white-on-cream panels, stone borders, restrained terracotta (dot, nav indices, subtle active highlight), 16px base, Newsreader headings + Inter body. Palette: cream #F3F1E7, ink #191919, terracotta #D97757, stone #D6D4C8. (Replaces the current dark #0f1117/#6c63ff portal theme.)

  • Chat = native (backend→Hermes) — NOT an iframe. Backend proxies to the client's

    • Hermes profile via the orchestrator MCP / send-reply (reference_hermes_orchestrator_mcp_architecture + read path reference_hermes_mcp_bridge). Frontend renders a portal-native chat.

  • ecom client = the-mall (existing; Linear team ECOM, dedicated mall-scraper Hermes

    • profile, canonical clients/the-mall/hermes/). Give it a Hermes chat binding; no new client dir.

03 Current architecture (verified 2026-06-21) 119 words
  • Frontend: Vue/Vite apps/client-portal/frontend → dev :5173; proxies /api/* → :5480.
  • Backend: FastAPI apps/client-portal/backend (main.py + client_reader.py) → :5480;

    • reads VAULT_ROOT=second-brain/ (profile.md frontmatter, deliverables/, artifact manifest).

  • Routes: /clients/:slug/{profile,deliverables,artifacts,transcripts,dashboard,hermes/chat}

    • + ClientNotFound. ClientLayout.vue is the only shared wrapper — a TOP header + HORIZONTAL nav (the thing to refactor into a left sidebar).

  • HermesChatView + DashboardView currently just iframe hermes.chat_url /

    • hermes_dashboard_url from profile.md — no live Hermes wiring.

  • No auth in the app (slug-in-URL only; Caddy basicauth on /clients/* in prod, secret

    • gbautomation/core/client-portal-basic-auth).

  • NOTE: localhost:9119 is the separate hermes-agent dashboard (hermes_cli.main web),

    • NOT the portal. The portal is its own app styled to look like that dashboard.

05 Phased build 193 words
  • P1 — Report Paper shell. Refactor ClientLayout.vue from horizontal-nav-on-dark to a

    • 2-column grid: left sidebar (.nav) + topbar with the brand lockup = Hermes agent logo, GB logo to its right. Encode the Variant-1 theme tokens (cream/terracotta) as the portal's CSS vars (replace App.vue dark vars). All existing views inherit it unchanged. Demoable at :5173.

  • P2 — Sign in as ecom (the-mall). A /login (or simple client picker) that lands

    • the-mall on /clients/the-mall/dashboard. Keep it light — reuse the prod Caddy basicauth model; app-level session optional. Add the Dashboard tab as the post-login landing.

  • P3 — Native Hermes chat. Backend POST /api/clients/{slug}/chat → send to the client's

    • Hermes profile via the orchestrator MCP (send/reply); GET to poll replies (read via the MCP bridge / state.db). Replace the HermesChatView iframe with a native chat UI. Deepest piece — the portal backend must reach the Mini's Hermes (run the backend on the Mini, or call the orchestrator MCP over the tailnet). This is the "make sure we can communicate with Hermes" deliverable.

  • P4 — Index tabs. Add the Plans / Tasks-Board / Activity routes + views + backend routes

    • per the map. Dashboard landing aggregates a board + activity snapshot.
