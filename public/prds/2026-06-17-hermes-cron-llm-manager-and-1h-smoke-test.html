03 B. The LLM-as-manager cron contract (NEW — supersedes no-agent script mode) 155 words

Today most Hermes crons run mode: no-agent (Script: foo.sh, stdout delivered raw). New contract: every cron is a Hermes cron that invokes a cheap manager-tier LLM (e.g. gpt-5-mini / the current mini model — set in config, NOT the expensive build model) as a manager + reporter:

  1. Run the underlying skill/script (the heavy work — scrape, build, brief — may still be a tool).
  2. Assess the result → structured {outcome: ok|partial|fail, why, metrics} (LLM judgment, not exit code only).
  3. Receipt → write cron_runs (+ cron_run_outputs) + update hermes_cron_catalog.last_green_at.
  4. Trace → Langfuse span for the turn; Card → Hermes Kanban card create/update.
  5. Report → one-line digest appended to the morning-brief feed (deliver: origin only if action needed).

Manifest change: each hermes/cron/crons.manifest.yaml entry gets mode: managed + manager_model + tool: <script|skill> instead of mode: script. The manager prompt is a shared template (carries the TAC prompt-format contract; authored once, like the Canopy tac-contract-shared mixin).

Acceptance matrix (GREEN = all true)

  • Supabase receipts: every fired tick wrote a cron_runs row; hermes_cron_catalog.last_green_at advanced for each.
  • LLM-manager: every tick produced a structured outcome (ok/partial/fail + why) — not raw stdout. Confirm via cron_run_outputs.agent_summary non-empty.
  • Kanban: each managed cron created/updated a card (agent_runs row); card observability contract present.
  • Langfuse: every tick has a trace; check-langfuse-logs returns the window's spans.
  • morning-brief: the digest aggregated the window's runs (counts match cron_runs).
  • worktree: the build cron ran in an isolated worktree and cleaned up (no leftover worktree, no dirty main).
  • git: the git cron landed via branch→PR→squash; main clean; no force-push to main.
  • cost: total manager spend within a small budget (e.g. < $1) — proves gpt-mini is the manager tier.

Procedure (Gelby, on the Mini)

  1. Render a smoke profile from hermes-gbauto (managed-mode crons) on the Mini; install all crons PAUSED.
  2. Apply the smoke schedule override (the accelerated cadences above) — a separate overlay, not the prod manifest.
  3. hermes cron resume the smoke set; run for 60 min; capture receipts.
  4. Validate the acceptance matrix from Supabase (cron_runs/cron_run_outputs/hermes_cron_catalog) + Kanban (agent_runs) + Langfuse.
  5. Tear down: pause + remove the smoke crons + the schedule override; emit a smoke report (per-job green/red + cost).
  6. Only after GREEN: promote the managed-mode contract to the prod manifest + proceed with the Phase-4 cutover.
